## 1. 验收标准

PROJECT_PLAN §6 W16.3 验收标准：**M1.2 Alpha 阶段崩溃率 <3%**（crash-free users / crash-free sessions）。

「崩溃率」定义：
- **crash-free users**：未触发 unhandled error / unhandled promise rejection 的用户占比
- **crash-free sessions**：未触发崩溃的会话占比（一个用户可能有多个 session）

数据来源：Sentry dashboard → Releases → 选定 release → Crash Free Users / Sessions 百分比。

阈值 <3% 即「97% 以上的用户/会话无崩溃」，符合 Alpha 阶段质量基线（参考业界 SaaS Alpha 标准 <5%，M1.2 收紧到 <3%）。

## 2. 监控基础设施

### 2.1 Sentry SDK 接入（W12.3 落地，PR #14 Review 修复）

**文件**：`apps/playground/src/toolkit/sentry.ts`（172 行）

**核心导出**：
- `shouldEnableSentry(): boolean` —— 检查 DSN + DNT + GPC，决定是否启用
- `initSentry(): Promise<void>` —— ES dynamic import 懒加载 `@sentry/browser`，避免 ~80KB 进首屏
- `captureException(error, context?): void` —— 手动捕获异常（ErrorBoundary 调用）
- `captureMessage(message, level?): void` —— 捕获消息（如降级触发）
- `setAnonymousUser(userId): void` —— 设置匿名用户标识（无 PII）
- `_resetSentryForTesting(): void` —— 测试用重置模块状态

**初始化位置**：`apps/playground/src/layouts/PlaygroundLayout.astro` `<head>` 末尾的内联 `<script>`：

```astro
<script>
  import { initSentry } from '../toolkit/sentry.js';
  initSentry();
</script>
```

> 在 React 之前初始化，确保后续 React 组件内的运行时错误能被 ErrorBoundary 捕获后调用 `captureException()` 上报。

### 2.2 DSN 注入（环境变量）

- **变量名**：`PUBLIC_SENTRY_DSN`
- **读取方式**：`getSentryDsn()` 函数延迟读取 `import.meta.env.PUBLIC_SENTRY_DSN ?? ''`（W12 PR #14 Review 修复——原 W12.3 实现模块顶部 `const` 捕获导致测试无法注入）
- **未配置时**：`shouldEnableSentry()` 返回 `false`，`initSentry()` no-op，所有 `capture*` API 退化为 `console.error`，**playground 完全不上报**
- **配置位置**：Cloudflare Pages dashboard → lokvis-playground → Settings → Environment variables（Production）+ GitHub Actions env（构建期内联到客户端 bundle）

参考 `apps/playground/.env.example` 与 `apps/playground/DEPLOY.md` §5。

### 2.3 DNT 尊重

`shouldEnableSentry()` 检测两类隐私信号，任一为「拒绝跟踪」即不上报：

```typescript
if (navigator.doNotTrack === '1') return false;        // 老标准（IE/Firefox/Safari）
if ((navigator as Navigator & { globalPrivacyControl?: boolean }).globalPrivacyControl) {
  return false;                                          // 新标准（Firefox/Safari/Edge，Chrome 待跟进）
}
```

> W12 PR #14 Review 修复：原 W12.3 实现用 `as unknown as` 双断言访问 `window.doNotTrack`，违反 AGENTS.md 禁双断言约定。改用 `navigator.doNotTrack` + `navigator.globalPrivacyControl` 直接访问 + 单次 `as` 类型合并断言。

### 2.4 beforeBreadcrumb redact（6 类 breadcrumb）

`beforeBreadcrumb` 钩子对可能含文件名的 breadcrumb 类别同时 redact `message` 与 `data`：

```typescript
const sensitiveCategories = new Set([
  'ui.click',   // 点击目标可能含文件名（如 <button>Lokvis-resized-2026.png</button>）
  'ui.input',   // 输入框值
  'ui.key',     // 按键
  'fetch',      // fetch URL 可能含 base64 workflow
  'xhr',        // xhr URL
  'console',    // console.log 参数
]);
if (sensitiveCategories.has(breadcrumb.category ?? '')) {
  return { ...breadcrumb, message: '[redacted]', data: undefined };
}
```

> W12 PR #14 Review 修复：原 W12.3 实现仅 redact `message`，`data` 字段仍可能泄露 UI 点击目标。改为同时 redact message + data。

`navigation` 类 breadcrumb 原样返回（仅含 URL 路径，不含敏感信息；URL query 在 §2.5 beforeSend 阶段 redact）。

### 2.5 beforeSend URL redact

`beforeSend` 钩子剥离 URL 查询参数与 hash，仅保留 origin + pathname：

```typescript
beforeSend(event) {
  if (event.request?.url) {
    try {
      const u = new URL(event.request.url);
      const safeUrl = `${u.origin}${u.pathname}`;     // 丢弃 hash 与 query
      event.request = { ...event.request, url: safeUrl };
    } catch {
      event.request = { ...event.request, url: '[redacted-url]' };  // 非标准 URL 整段 redact
    }
  }
  return event;
}
```

**保护场景**：playground 支持通过 `?workflow=<base64>` 分享 workflow，base64 编码的 workflow JSON 可能含文件名 / 路径。`beforeSend` 剥离 query 后，Sentry 上报的 URL 仅含 `https://playground.lokvis.dev/sdk`，不含 workflow 内容。

> W12 PR #14 Review 修复：原 W12.3 实现仅截断 URL 到 200 字符，前 200 字符仍泄露 workflow 开头。改为完全剥离 query + hash。

### 2.6 ErrorBoundary 覆盖

**文件**：`apps/playground/src/components/ErrorBoundary.tsx`

5 个核心 demo 页（sdk / runtime / plugin / workflow / mcp）的 .astro 文件**全部**用 `<ErrorBoundary client:only="react">` 包裹 demo 组件：

```astro
<PlaygroundLayout title="..." active="sdk">
  <ErrorBoundary client:only="react">
    <SdkDemo />
  </ErrorBoundary>
</PlaygroundLayout>
```

**ErrorBoundary 行为**：
- 捕获子组件渲染异常 → 调用 `captureException(error, { componentStack })` 上报 Sentry
- 渲染 fallback UI（错误提示 + 重试按钮）
- **隔离**：单 demo 崩溃不影响其他 demo / playground shell（sidebar / header 仍可用）

> 14 个 .astro 页面（5 demo + 8 tools + index）均使用 ErrorBoundary 包裹客户端 React 组件（W12 PR #14 review 修复）。

## 5. 部署后验证步骤

### Step 1 — 配置 PUBLIC_SENTRY_DSN 环境变量

两种方式任选其一：

**方式 A（Cloudflare Pages dashboard）**：
- Cloudflare Pages dashboard → lokvis-playground → Settings → Environment variables（Production）
- 添加 `PUBLIC_SENTRY_DSN` = `https://<key>@sentry.io/<project>`
- 触发重新部署（push 到 dev 或手动 workflow_dispatch）

**方式 B（GitHub Actions env）**：
- 仓库 Settings → Secrets and variables → Actions → New repository secret
- 添加 `PUBLIC_SENTRY_DSN`（构建期内联到客户端 bundle）
- 在 `deploy-playground.yml` 的 build 步骤前加 `env: PUBLIC_SENTRY_DSN: ${{ secrets.PUBLIC_SENTRY_DSN }}`

> 推荐 A：Cloudflare Pages env 修改后无需重跑 GitHub Actions（但需触发一次重新部署使 Astro 构建期重新内联）。

### Step 2 — 触发若干 demo 操作

部署成功后访问 https://playground.lokvis.dev，执行：
- 进入 `/sdk` → 上传图片 → Run → Download
- 进入 `/workflow` → 上传图片 → Run Workflow
- 进入 `/mcp` → 切换 pluginSet → 勾选 batchMode

> 这些操作应**不触发**任何崩溃（除非有真实 bug，那正是 Sentry 要捕获的）。

### Step 3 — 在 Sentry dashboard 查看崩溃率

 Sentry dashboard → Releases → 选定 `playground@0.1.0`（或自定义 release）：

- **Crash Free Users**：24h 内未崩溃的用户占比
- **Crash Free Sessions**：24h 内未崩溃的会话占比

阈值：<3% 崩溃率 = ≥97% crash-free。

### Step 4 — 若 >3% 崩溃率

定位 hot crash → 触发 W16.6 Bug 修复：

1. Sentry dashboard → Issues → 按 event count 排序
2. 找到 top 1-3 hot crash → 查看堆栈
3. 在 GitHub 创建 issue，附 Sentry issue link + 堆栈
4. 修复 → PR → 部署 → 观察 24h 崩溃率变化
