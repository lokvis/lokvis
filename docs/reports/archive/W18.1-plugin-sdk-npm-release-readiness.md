## 4. 发版流程（运维执行）

### Step 1 — 应用 changeset 版本变更

```bash
$ pnpm changeset version
# 消耗 .changeset/*.md,更新各包 package.json version + 生成 CHANGELOG.md
```

预期结果：
- `packages/plugin-sdk/package.json` version: `0.2.2` → `0.3.0`
- `packages/plugin-sdk/CHANGELOG.md` 新增 `## 0.3.0` 章节
- 其他受影响包同步 bump

### Step 2 — 提交版本变更

```bash
$ git add .changeset/ packages/*/package.json packages/*/CHANGELOG.md
$ git commit -m "chore(release): apply changesets — plugin-sdk 0.3.0 + sdk 0.3.0 + ..."
$ git push origin dev
```

### Step 3 — 运行 pnpm build 确认构建通过

```bash
$ pnpm build
# 预期:所有包构建通过,dist/ 产物完整
```

### Step 4 — 配置 NPM_TOKEN（首次发版需要）

仓库 `lokvis/lokvis` → Settings → Secrets and variables → Actions → New repository secret：

- `NPM_TOKEN` = npmjs.com Access Token（Automation 类型，权限 Publish）

> npm provenance 已在 release.yml 启用（`NPM_CONFIG_PROVENANCE: 'true'` + `id-token: write`），
> 需 npm 账号开启 2FA 并支持 provenance。

### Step 5 — 打 tag 触发 release workflow

```bash
# 在 dev 分支打 tag（会触发 beta channel → dist-tag=beta）
# 或合并到 main 后打 tag（会触发 stable channel → dist-tag=latest）
$ git tag v0.3.0
$ git push origin v0.3.0
# 自动触发 release.yml,detect-release-channel 检测 tag 所在分支
```

**channel 判定**（`.github/workflows/release.yml` L36-68）：
- tag commit 在 `main` 分支祖先 → `stable` → dist-tag=`latest`
- tag commit 在 `dev` 分支祖先 → `beta` → dist-tag=`beta`
- 其他 → 按命名约定 fallback

### Step 6 — 验证发布成功

```bash
# 验证包已发布
$ npm view @lokvis/plugin-sdk@0.3.0
# 应返回包元数据(version / dist / dist-tags / readme)

# 测试安装
$ npm install @lokvis/plugin-sdk@0.3.0
$ node -e "import('@lokvis/plugin-sdk').then(m => console.log(Object.keys(m)))"
# 应输出:['definePlugin', 'createCapabilityImpl', 'createBlobCapabilityImpl',
#         'createMergeCapabilityImpl', 'createSplitCapabilityImpl', 'definePanel',
#         'defaultDeriveOutputMetadata', ...]
```

在 npmjs.com 搜索 `@lokvis/plugin-sdk`，确认：
- 版本 `0.3.0` 出现在版本列表
- dist-tags（`latest` 或 `beta`）指向 `0.3.0`
- README 渲染正常（含 Status: Alpha + Quick start + 3 工厂表 + PluginContext API 表）
- LICENSE 为 MIT
