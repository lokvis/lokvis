## 3. 部署步骤（运维执行）

> 以下步骤对应 `apps/playground/DEPLOY.md` §2-§3，按顺序执行即可上线。

### Step 1 — 创建 Cloudflare Pages 项目

在 Cloudflare dashboard → Workers & Pages → Create → Pages → Upload assets 创建项目：

- **Project name**：`lokvis-playground`
- **Production branch**：`dev`
- **Framework preset**：None
- **Build command**：留空（构建在 GitHub Actions 里跑，Pages 只接收 `wrangler pages deploy` 推送的产物）
- **Build output directory**：`apps/playground/dist`

> ⚠️ 不要配置 Cloudflare Pages 自带的 Git integration 构建命令——构建在 GitHub Actions 里跑（见 Step 6），Pages 只接收 `wrangler pages deploy` 推送的产物。

### Step 2 — 创建 Cloudflare API Token

在 https://dash.cloudflare.com/profile/api-tokens 创建 API Token：

- 权限：`Account → Cloudflare Pages → Edit` + `Account → Account Settings → Read`
- 复制 Token 值（仅显示一次）
- 在 dashboard 右下角找到 Account ID

### Step 3 — 配置 GitHub Actions Secrets

仓库 `lokvis/lokvis` → Settings → Secrets and variables → Actions → New repository secret：

- `CLOUDFLARE_API_TOKEN` = Step 2 创建的 Token
- `CLOUDFLARE_ACCOUNT_ID` = dashboard 右下角的 Account ID

### Step 4 — 绑定自定义域名

在 Cloudflare Pages dashboard → `lokvis-playground` → Custom domains → Set up a custom domain：

- 输入 `playground.lokvis.dev`
- Cloudflare 自动添加 CNAME 记录（指向 `lokvis-playground.pages.dev`）
- 等待证书签发（1-5 分钟），状态变 Active

> 若 `lokvis.dev` 域名也在 Cloudflare 管理，DNS 配置全自动；若在其他注册商，需手动添加 CNAME：`playground → lokvis-playground.pages.dev`。

### Step 5 — 生成 PWA PNG 图标

按 `apps/playground/DEPLOY.md` §8 用 sharp 从 `icon.svg` 生成 3 个 PNG：

```bash
cd apps/playground
node -e "
import('sharp').then(async ({default: sharp}) => {
  const svg = await sharp('public/icon.svg').png().toBuffer();
  await sharp(svg).resize(192, 192).toFile('public/icon-192.png');
  await sharp(svg).resize(512, 512).toFile('public/icon-512.png');
  const inner = await sharp(svg).resize(410, 410).toBuffer();
  await sharp({create:{width:512,height:512,channels:4,background:'#09090b'}})
    .composite([{input:inner, gravity:'center'}]).png().toFile('public/icon-maskable-512.png');
});
"
git add apps/playground/public/icon-192.png apps/playground/public/icon-512.png apps/playground/public/icon-maskable-512.png
git commit -m "feat(playground): PWA PNG icons (192/512/maskable-512)"
git push origin dev
```

> maskable 图标的 safe zone：核心内容必须位于中心 80% 区域（512×512 中 410×410 内）。

### Step 6 — 触发部署

两种触发方式任选其一：

**自动触发**：push 到 `dev` 分支且 `apps/playground/**` 路径下有文件变更，自动触发 `deploy-playground.yml`。

**手动触发**：GitHub → Actions → Deploy Playground → Run workflow → 选择 `dev` 分支 → Run。

部署 workflow 执行步骤：
1. checkout 代码
2. pnpm 9.12.0 + Node 22 安装依赖（`pnpm install --frozen-lockfile`）
3. `pnpm build`（全量构建，因 playground 依赖 `@lokvis/*` 子包的 dist 产物）
4. `cloudflare/wrangler-action@v3` 把 `apps/playground/dist` 推送到 `lokvis-playground` Pages 项目

`dev` 分支推送 = production 部署。

### Step 7 — 验证部署

访问 https://playground.lokvis.dev 验证：

1. **首页加载**：能看到 Lokvis Playground 品牌条 + sidebar（Demos / Tools / More 三组）
2. **5 个 demo 页可访问**：`/sdk` `/runtime` `/plugin` `/workflow` `/mcp` 直接访问不 404（_redirects fallback 生效）
3. **SW 注册**：DevTools → Application → Service Workers 显示 `sw.js` registered & activated；Console 输出 `[SW] registered /`
4. **PWA 安装提示**：地址栏右侧出现安装图标；Chrome DevTools → Application → Manifest 显示所有图标无 warning
5. **COOP/COEP 头**：DevTools → Network → 主文档请求 → Response Headers 含 `cross-origin-opener-policy: same-origin` + `cross-origin-embedder-policy: require-corp`
6. **离线可用**：DevTools → Application → Service Workers → Offline → reload，页面 fallback 到 `offline.html`
7. **Sentry（可选）**：若配置了 `PUBLIC_SENTRY_DSN`，DevTools → Network 应有到 `sentry.io` 的 POST 请求；未配置则无（no-op）
