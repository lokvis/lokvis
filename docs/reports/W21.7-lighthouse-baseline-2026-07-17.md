## 3. 瓶颈诊断

### 3.1 LCP 元素

```
div.cm-editor > div.cm-scroller > div.cm-content > div.cm-line
nodeLabel: "// `lokvis` is a ready Runtime injected by the playground."
```

LCP 元素是 Playground 首页 CodeMirror 编辑器的第一行代码。它需要:
1. 加载 codemirror chunk(144KB)
2. 加载 react-vendor(58KB)+ vendor(68KB)
3. React 水合 `<Playground>` 组件
4. `lazy(() => import('./CodeEditor'))` 触发 CodeEditor chunk 加载
5. CodeMirror 初始化 + 渲染首行

仅 1 个 render-blocking CSS(PlaygroundLayout 全局样式),体积小但延迟显著。

## 4. 优化建议(留待后续任务)

### P0: LCP 优化(目标 <2.5s)

1. **CodeEditor 延迟到用户交互后再加载**
   - 当前:`Playground` 组件首屏即渲染 `<CodeEditor>`(尽管已 `lazy`)
   - 建议:首屏用 `<textarea>` 占位,用户首次 focus / 切换到 editor tab 时再动态替换为 CodeMirror
   - 预期:LCP 从 6.9s 降到 ~1.5s(回到 FCP 水位)

2. **或:首页改为不依赖 CodeMirror 的入口**
   - 把 Code Editor demo 移到 `/playground` 子路径
   - 首页改为 SDK 快速介绍 + CTA 按钮(无重型 JS)
   - 预期:LCP <1s

### P1: FID / TBT 优化(目标 <100ms / <200ms)

3. **CodeMirror chunk 进一步拆分**
   - 当前 codemirror chunk 144KB 含全部扩展,首屏只用基础编辑器
   - 建议:把 `@codemirror/lang-javascript` / `@codemirror/theme-one-dark` 等拆为独立 chunk
   - 预期:首屏 codemirror chunk 降到 ~60KB

4. **React 水合优化**
   - 当前 198ms 长任务来自 React 19 水合
   - 建议:用 `useDeferredValue` 延迟非关键 state 水合
   - 预期:TBT 降到 <150ms

### P2: CSS 优化(目标 <500ms)

5. **PlaygroundLayout.css 关键 CSS 提取**
   - 当前 8KB CSS 全部 render-blocking
   - 建议:把首屏必需的 sidebar / header 样式内联到 `<style is:inline>`,其余 defer
   - 预期:render-blocking 浪费从 724ms 降到 ~200ms

## 6. 复现步骤

```bash
# 1. 构建 playground
pnpm --filter @lokvis/playground build

# 2. 启动 preview
cd apps/playground && pnpm exec astro preview --port 4321 --host 127.0.0.1 &

# 3. 跑 Lighthouse(performance 类别,mobile 模拟默认)
npx lighthouse@12 http://127.0.0.1:4321/en/ \
  --only-categories=performance \
  --output=json --output=html \
  --output-path=./docs/reports/lighthouse-$(date +%Y-%m-%d) \
  --chrome-flags="--headless=new --no-sandbox"

# 4. 查看报告
open ./docs/reports/lighthouse-$(date +%Y-%m-%d).report.html
```

**跑分模式**:本次使用 Lighthouse 默认 mobile 模拟(4x CPU 节流 + Slow 3G)。Desktop 模式跑分应显著更优(LCP 预计 <2s),但 mobile 是 Alpha 验收基线。
