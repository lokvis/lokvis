## 一、路线图总览

### 1.1 三年四阶段战略

```
2026 H2            2027 H1            2027 H2            2028 H1            2028 H2            2029 H1
│                  │                  │                  │                  │                  │
├─ Phase 1: MVP ───┼─ Phase 2: 扩展 ──┼─ Phase 3: 生态 ──┼─ Phase 4: 平台 ──────────────────────┤
│  0-6 月          │  6-12 月          │  12-24 月         │  24-36 月                          │
│                  │                  │                  │                                    │
│  Image WS        │  PDF + Video WS  │  Marketplace     │  Enterprise                        │
│  本地处理验证     │  Plugin SDK      │  AI Workflow     │  Desktop App                       │
│  基础 SEO         │  Cloud Pro       │  开发者生态       │  国际化                            │
│                  │                  │                  │  盈利                              │
└──────────────────┴──────────────────┴──────────────────┴────────────────────────────────────┘
```

### 1.2 阶段目标摘要

| 阶段 | 时间 | 核心目标 | 关键指标 | 团队规模 |
|------|------|---------|---------|---------|
| **Phase 1** | 2026.07-2026.12 | Image Workspace MVP 上线，验证 PMF | 5K-20K 月访问 / 100-500 Pro | 1-2 人 |
| **Phase 2** | 2027.01-2027.06 | PDF + Video Workspace，开放 Plugin SDK | 3万-10万月访问 / $271K ARR | 2-3 人 |
| **Phase 3** | 2027.07-2028.06 | Marketplace 上线，开发者生态启动 | 10万-50万月访问 / $1.77M ARR | 4-6 人 |
| **Phase 4** | 2028.07-2029.06 | 企业版、桌面版、国际化 | 50万+月访问 / $10.57M ARR | 8-12 人 |

### 1.3 路线图设计原则

1. **聚焦优先于横向扩张**：每个阶段只专注 1-2 个 Workspace，避免过早铺开
2. **收入驱动**：Phase 1 末必须有付费验证，Phase 3 末必须盈利可期
3. **生态优先于功能**：Phase 2 起开发者生态优先于官方功能开发
4. **数据驱动决策**：每个阶段结束需达成明确指标，未达成不进入下一阶段
5. **保留战略灵活性**：每季度 review，允许根据市场反馈调整路线

## 二、Phase 1: MVP 验证（2026.07-2026.12）

### 2.1 阶段核心命题

> **验证："本地处理 + 工作流编排" 的产品市场契合度（PMF）**

具体回答三个问题：
1. 用户是否愿意在浏览器内完成图像处理任务？
2. 用户是否愿意为"批量处理 + 工作流保存"付费？
3. SEO 流量获取成本与转化率是否支撑商业模式？

## 十、成功标准与失败预案

### 10.1 项目成功定义

**3 年成功标准（2029.06）**：
- ARR ≥ $5M（底线）/ $10M（目标）
- MAU ≥ 100K（底线）/ 150K（目标）
- 员工数 ≥ 8 人
- 盈利或清晰盈利路径
- Marketplace 1000+ 工作流
- 开发者社区 500+ 活跃

**5 年成功标准（2031）**：
- ARR ≥ $30M
- 成为"浏览器工作流运行时"事实标准
- IPO 或战略并购退出路径清晰

### 10.2 失败预案

**场景 1：Phase 1 末未达 PMF**
- 触发条件：MAU <1,000 或 Pro 用户 <10
- 应对：用户访谈 50+ 人，识别核心问题
- 选项 A：调整产品定位（如聚焦单一垂直，如电商图片处理）
- 选项 B：转型为 B2B SaaS（企业专用工具）
- 选项 C：开源所有代码，转为 side project

**场景 2：Phase 2 末增长停滞**
- 触发条件：连续 3 个月 MAU 环比下降
- 应对：深度数据分析，识别流失原因
- 选项 A：加大付费获客
- 选项 B：聚焦留存而非获客
- 选项 C：调整商业模式（如完全免费 + 企业授权）

**场景 3：资金链断裂**
- 触发条件：现金流 <3 个月
- 应对：紧急融资 / Lifetime Deal / 裁员
- 极端：项目开源托管，社区维护

## 十二、路线图总结

Lokvis 项目三年路线图的核心逻辑可概括为：

```
聚焦验证 → 横向扩展 → 生态构建 → 平台化
   │           │           │           │
   │           │           │           └─ $10M ARR / 50万+ MAU
   │           │           └─ Marketplace / 开发者生态
   │           └─ 多 Workspace / Plugin SDK / Cloud Pro
   └─ Image MVP / PMF 验证 / 首批付费
```

**关键成功因素**：
1. **Phase 1 极度聚焦**：不铺开工具数量，深挖 Image Workspace
2. **Phase 2 商业化验证**：必须达到 $15K+ MRR 才能进入 Phase 3
3. **Phase 3 生态冷启动**：官方先行 1000+ 工作流，再开放 UGC
4. **Phase 4 平台化**：企业版 + 桌面版 + 开放 API 构筑护城河

**最大风险**：
- 团队资源瓶颈（O1）
- Marketplace 冷启动（B1）
- SEO 流量下行（M1）

**应对核心**：
> 保持纪律性，每阶段专注核心目标，用数据驱动决策，不冒进不贪多。

只要 Phase 1 能够验证 PMF，后续阶段的成功概率将显著提升。Lokvis 的长期价值在于建立"浏览器工作流运行时"的事实标准，这一目标的实现需要 3-5 年的持续投入。
