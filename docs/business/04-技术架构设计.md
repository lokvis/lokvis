# Lokvis 项目白皮书 · 04 技术架构设计

> **文档版本**：v1.0
> **发布日期**：2026-06-28
> **设计原则**：Local First, Cloud Optional, Open Core, Stable Core + Replaceable Engine

---

## 一、架构总览

### 1.1 五层架构

```
┌─────────────────────────────────────────────────────┐
│  UI Layer                                           │
│  Astro 7 (SEO 内容) + React 19 (Workspace SPA)      │
├─────────────────────────────────────────────────────┤
│  Workflow Layer                                     │
│  JSON 声明式工作流 + 可视化编辑器 + 市场              │
├─────────────────────────────────────────────────────┤
│  Runtime Layer (浏览器内核)                          │
│  调度 / 状态 / 事件总线 / 历史 / Asset Store          │
├─────────────────────────────────────────────────────┤
│  Capability Layer (能力注册中心)                     │
│  Resize / Compress / Convert / OCR / Caption 等     │
├─────────────────────────────────────────────────────┤
│  Engine Layer (可替换引擎)                           │
│  FFmpeg.wasm / Squoosh / pdf-lib / Whisper / WebCodecs│
└─────────────────────────────────────────────────────┘
```

### 1.2 三大设计原则

> **Everything is a Package, Everything is a Capability, Everything Runs Locally.**

1. **Everything is a Package**：所有功能拆成独立 Package，便于 Monorepo 管理、开源和复用
2. **Everything is a Capability**：Runtime 永远只调度能力（Capability），不依赖具体引擎
3. **Everything Runs Locally**：所有核心工作流在浏览器执行，Cloudflare 只承担边缘服务

### 1.3 四个设计准则

| 准则 | 含义 | 实现要点 |
|------|------|---------|
| **Stable Core** | Runtime/Schema 变化最慢，几年保持兼容 | 严格版本管理，无 Breaking Change |
| **Replaceable Engine** | 底层能力通过适配层接入 | FFmpeg→WebCodecs 无需改 Runtime |
| **Extensible Everything** | Engine/Capability/Workflow/UI/Exporter 都可扩展 | 统一注册机制 |
| **Local First, Cloud Optional** | 无账号、无网络、无 Cloud 仍可运行 | Cloud 仅负责同步/市场/账户/AI |

### 2.2 依赖规则（最重要）

```
lokvis-cloud ──依赖──→ lokvis-open
                        ▲
                        │
              永远不能反向依赖
```

**核心约束**：
- `lokvis-open` 中的任何 Package **绝不能** import `lokvis-cloud`
- Runtime **绝不能**知道 React（UI 框架）
- Schema **绝不能**知道 Runtime
- Plugin **绝不能**知道 Cloud

### 2.3 Package 生命周期

| Package | 升级频率 | 版本策略 |
|---------|---------|---------|
| schema | 季度 | 严格 semver，无 Breaking Change |
| runtime | 月度 | semver |
| sdk | 月度 | semver |
| engine-* | 随上游 | 跟随 FFmpeg/WebCodecs 等 |
| plugin-* | 按需 | 独立版本 |
| cloud/* | 每日 | 内部版本 |

## 三、Runtime 层设计（核心）

### 3.1 Runtime 职责

Runtime 是整个系统的"浏览器操作系统"，唯一职责：

```
Input → Run → Output
```

具体能力：
- 工作流调度（Workflow Execution）
- 任务队列管理（Task Queue）
- 状态管理（State Management）
- 事件总线（Event Bus）
- 历史记录（History / Undo / Redo）
- Asset 管理（Asset Store）
- 能力解析（Capability Resolver）
- 插件加载（Plugin Loader）

### 3.2 Runtime API 设计（第一版，必须克制）

```typescript
// 核心 Runtime API
interface LokvisRuntime {
  // 工作流执行
  run(workflow: Workflow, inputs: Asset[]): Promise<WorkflowResult>;
  cancel(workflowId: string): Promise<void>;
  pause(workflowId: string): Promise<void>;
  resume(workflowId: string): Promise<void>;

  // 历史与撤销
  history(workflowId: string): Promise<HistoryEntry[]>;
  undo(workflowId: string): Promise<void>;
  redo(workflowId: string): Promise<void>;

  // Asset 管理
  importAsset(file: File | Blob): Promise<AssetId>;
  getAsset(id: AssetId): Promise<Asset>;
  exportAsset(id: AssetId, format: string): Promise<Blob>;

  // 能力查询
  capabilities(): Promise<Capability[]>;
  hasCapability(name: string): Promise<boolean>;
}
```

**设计要点**：
- **永远只有 Asset**，没有 Image/PDF/Video 等具体类型 API
- **永远只有 Capability**，没有 FFmpeg/ImageMagick 等具体引擎 API
- 第一版**不支持** Branch/Loop/Condition，只支持 Linear Workflow

### 3.3 Event Bus 设计

所有操作发出标准事件，Analytics/Undo/AI/Plugin/协作都监听事件，无需侵入核心逻辑。

```typescript
type LokvisEvent =
  | { type: 'asset:imported'; assetId: AssetId; metadata: AssetMetadata }
  | { type: 'workflow:started'; workflowId: string; workflow: Workflow }
  | { type: 'node:started'; workflowId: string; nodeId: string; inputs: Asset[] }
  | { type: 'node:finished'; workflowId: string; nodeId: string; outputs: Asset[] }
  | { type: 'node:failed'; workflowId: string; nodeId: string; error: Error }
  | { type: 'workflow:completed'; workflowId: string; result: WorkflowResult }
  | { type: 'export:completed'; assetId: AssetId; format: string; size: number }
  | { type: 'history:changed'; workflowId: string; entries: HistoryEntry[] };

interface EventBus {
  on<T extends LokvisEvent['type']>(
    type: T,
    handler: (event: Extract<LokvisEvent, { type: T }>) => void
  ): () => void;
  emit(event: LokvisEvent): void;
}
```

### 3.4 Asset 模型（统一抽象）

```typescript
interface Asset {
  id: AssetId;                    // 唯一标识
  type: 'image' | 'video' | 'audio' | 'pdf' | 'text' | 'data' | 'unknown';
  metadata: AssetMetadata;        // 尺寸、格式、时长等
  blob: BlobHandle;               // OPFS 中的引用，不直接持有内存
  preview?: PreviewHandle;        // 缩略图
  history: HistoryEntry[];        // 处理历史
  tags: string[];                 // 用户标签
  createdAt: number;
  updatedAt: number;
}

interface AssetMetadata {
  mimeType: string;
  size: number;                   // 字节数
  dimensions?: { width: number; height: number };  // 图像/视频
  duration?: number;              // 视频/音频（秒）
  pages?: number;                 // PDF
  format: string;                 // png, mp4, pdf, mp3...
}
```

**关键设计**：Runtime 只操作 AssetId，不直接持有 File 或 Blob。所有大文件通过 OPFS 引用，避免内存爆炸。

## 五、Capability Layer（能力注册中心）

### 5.1 能力抽象

Runtime 永远不知道 FFmpeg，只知道 Capability：

```typescript
// Capability 定义
interface Capability {
  name: string;                    // 'image.resize'
  description: string;
  inputTypes: Asset['type'][];     // ['image']
  outputTypes: Asset['type'][];    // ['image']
  params: CapabilityParam[];       // 参数 Schema
  performance: 'fast' | 'medium' | 'slow';  // 性能预估
}

// Capability 实现（由 Plugin 注册）
interface CapabilityImplementation {
  capability: string;              // 'image.resize'
  engine: string;                  // 'squoosh' | 'ffmpeg' | 'webcodecs'
  execute(
    inputs: Asset[],
    params: Record<string, unknown>,
    context: ExecutionContext
  ): Promise<Asset[]>;
}
```

### 5.2 能力注册示例

```typescript
// plugin-image 注册能力
import { definePlugin } from '@lokvis/plugin-sdk';

export default definePlugin({
  name: 'lokvis-image-tools',
  version: '1.0.0',
  capabilities: [
    {
      name: 'image.resize',
      description: 'Resize image to specified dimensions',
      inputTypes: ['image'],
      outputTypes: ['image'],
      params: [
        { name: 'width', type: 'number', required: false },
        { name: 'height', type: 'number', required: false },
        { name: 'fit', type: 'enum', values: ['cover', 'contain', 'fill'] }
      ],
      performance: 'fast'
    },
    {
      name: 'image.compress',
      description: 'Compress image with specified quality',
      inputTypes: ['image'],
      outputTypes: ['image'],
      params: [
        { name: 'format', type: 'enum', values: ['webp', 'avif', 'jpeg', 'png'] },
        { name: 'quality', type: 'number', min: 0, max: 100 }
      ],
      performance: 'fast'
    }
  ],
  engine: 'squoosh'  // 使用 Squoosh WASM 引擎
});
```

### 5.3 引擎可替换性

```
Capability: image.encode
    ├── Engine: squoosh (WASM)
    ├── Engine: webcodecs (浏览器原生)
    └── Engine: imagemagick (WASM)
```

Runtime 根据浏览器能力、性能、用户偏好自动选择最佳引擎。

## 六、Engine Layer（可替换引擎）

### 6.1 引擎适配层

```typescript
interface EngineAdapter {
  name: string;                    // 'ffmpeg' | 'squoosh' | 'pdf-lib'
  version: string;
  supportedCapabilities: string[]; // ['video.transcode', 'video.trim']
  isSupported(): Promise<boolean>; // 浏览器能力检测
  initialize(): Promise<void>;     // 加载 WASM
  dispose(): Promise<void>;        // 释放资源
}
```

### 6.2 引擎选型

| 能力域 | 主引擎 | 备选引擎 | 说明 |
|--------|--------|---------|------|
| 图像编解码 | Squoosh (WASM) | WebCodecs | Squoosh 开源可复用，WebCodecs 原生加速 |
| 视频转码 | FFmpeg.wasm | WebCodecs | ffmpeg.wasm 3 万星，生态成熟 |
| PDF 处理 | pdf-lib | - | 成熟 TS 库，无 WASM 依赖 |
| 音频处理 | FFmpeg.wasm | WebAudio API | 复用视频引擎 |
| OCR | Tesseract.js | Whisper.cpp | 浏览器内 OCR 成熟方案 |
| 语音识别 | Whisper.cpp (WASM) | Web Speech API | 本地 AI 推理 |
| SQLite | sql.js | SQLite-WASM + OPFS | 本地数据库 |
| 图像分割 | SAM (WASM) | - | 未来方向 |

### 6.3 跨域隔离配置（关键工程痛点）

FFmpeg.wasm 需要 SharedArrayBuffer，必须配置：

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

**影响**：第三方资源（分析、广告、字体）需配合 CORP 头。

**解决方案**：
- 所有第三方资源通过自建 CDN 代理
- Cloudflare Workers 统一添加安全头
- 非 Chromium 浏览器降级为单线程模式

**结论**：Lokvis 80% 是内容（SEO 页面），20% 是 Workspace SPA。Astro 负责内容 Shell，React 负责 Workspace。

## 九、Cloudflare 基础设施

### 9.1 服务映射

| Cloudflare 服务 | Lokvis 用途 | 数据类型 |
|----------------|----------|---------|
| **Pages** | Astro 站点托管 | 静态 HTML/JS/CSS |
| **Workers** | API、鉴权、Marketplace | 边缘计算 |
| **D1** | 元数据存储 | Workflow/User/Plugin/Purchase |
| **KV** | 缓存、Feature Flag、Session | 键值对 |
| **R2** | 文件存储 | Workflow JSON/Plugin ZIP/预览图 |
| **Queues** | 异步任务 | 缩略图生成/索引/通知 |
| **Vectorize** | 语义搜索 | Marketplace 搜索 |
| **Durable Objects** | 后期多人协作 | 实时同步状态 |
| **Turnstile** | 防滥用 | 登录/评论 |
| **Analytics** | 基础分析 | 流量/性能 |

### 9.2 数据流（核心原则：Cloud 不参与执行）

```
用户浏览器
    │
    ├── 导入文件 → OPFS (本地存储)
    │
    ├── 运行 Workflow → Runtime (本地执行)
    │   ├── 调用 Capability → Plugin → Engine (WASM)
    │   └── 事件 → Event Bus (本地)
    │
    ├── 导出结果 → 本地下载
    │
    └── 可选：保存 Workflow → Cloudflare R2 (同步)
        │
        └── Cloudflare Workers (API)
            ├── D1 (元数据)
            ├── KV (缓存)
            └── R2 (文件)
```

**关键**：Workflow 执行完全在浏览器，Cloudflare 只负责存储和同步。

## 十、本地存储设计

### 10.1 存储分层

```
┌──────────────────────────────────┐
│  IndexedDB (Dexie)               │  ← 元数据、历史、设置
│  - Workflow 历史                  │
│  - Asset 元数据                   │
│  - 用户设置                       │
│  - Recent Files                  │
├──────────────────────────────────┤
│  OPFS (Origin Private File System)│  ← 大文件持久化
│  - 用户导入的原始文件              │
│  - Workflow 中间产物              │
│  - WASM 模块缓存                  │
└──────────────────────────────────┘
```

### 10.2 为什么用 OPFS

| 方案 | 容量 | 性能 | 持久性 |
|------|------|------|--------|
| IndexedDB | ~50% 磁盘 | 中 | 浏览器清理可能丢失 |
| **OPFS** | **~60% 磁盘** | **高（同步访问）** | **持久** |
| File System Access API | 无限 | 高 | 真实文件系统 |

**选择 OPFS**：
- 不占用 IndexedDB 配额
- 支持同步访问（Worker 中高性能读写）
- 数据直接落磁盘块
- Adobe Photoshop Web、Figma 等已验证

## 十三、技术风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| Runtime API 公开后无法修改 | 极高 | 第一版极度克制，只暴露最小 API |
| 大文件 OOM | 高 | 天然 Streaming，分片处理 |
| Safari/Firefox 兼容性 | 中 | 优先 Chromium（75%+），渐进降级 |
| WASM 包体积（FFmpeg 25MB） | 中 | 按需加载，Service Worker 缓存 |
| 跨域隔离配置影响第三方 | 中 | 自建 CDN 代理 |
| Plugin 安全性 | 中 | 权限模型，沙箱执行 |
